## Findings within the 41 covered files

No embedded live credential, owner subject, personal host path, actual private routing address, customer records, or literal Content Blooms name was found. There is one newly exported consumer-name condition below. Merely imported files remain outside this coverage.

- **Fixture material is explicit synthetic data.** Test helpers generate Ed25519 keypairs at runtime, use `new Uint8Array(32).fill(...)`, repeated hex test integrity keys, `identity:test`, `tenant:test`, `node:test`, `credential:test` and similarly labelled placeholders. `password: "synthetic-only"`, `template1`, localhost port 5432 and test LOGIN names describe injected disposable PGlite pool fixtures, not a stored production connection. Reserved `example.test`/`example.invalid` addresses and the literal `synthetic CA material only` are not real endpoints or a deployable certificate. User/private values in typed request, database and authentication parameters are runtime inputs, not embedded records.
- **Privileged fixture setup is labelled.** `managed-native-session.ts` explicitly resets disposable session authorization for setup/fake-node work, wraps restricted test LOGIN transactions and identifies the PGlite TEMP metadata adaptation. It is not a production grants recipe or evidence of independent physical PostgreSQL connections. Other helpers deliberately use synthetic provider transport ports and in-memory/disposable journals. Their passing behavior was not re-executed or certified here.
- **Launchers are executable entrypoints, not hidden install scripts.** The two selected scripts import trusted operator-supplied `.mjs` modules only under explicit invocation, capture signal lifecycle and fixed release imports, and expose generic absolute-path help examples. Such imports execute operator JavaScript; file permission checks do not make them a sandbox. They can acquire real resources when intentionally configured and run, so source disclosure clearance must not be described as permission to start them. No embedded production configuration or automatic package install was found.
- **Test side effects are explicit and fixture-bounded in the read code.** Temporary files/directories, test-generated keys, SQL test role creation and cleanup are ordinary test setup. Launcher tests invoke only help/invalid arguments in subprocesses or inject release/operator/server ports. Compiled tests assume previously generated `dist-vps`, read assets and use synthetic hosts/pools. Their comments distinguish denied native setup from real calls. This source review neither ran those tests nor proves every imported fixture's complete containment.
- **Queue integration is generic application glue.** `control_room_queue`, `native-task-delivery`, `abs-feed-collection` and pinned package/version references are public protocol/schema names, not private deployment identifiers. Upstream constructor ports are supplied by composition, no installer is embedded, queue payloads are canonical locators, and the source explicitly separates operational pickup from execution authority. This is description, not acceptance of those contracts.
- **Idea text is supplied by callers.** Discussion and owner/lifecycle services use request/session fields rather than baked-in business ideas. Deterministic synthesis is explicitly labelled extractive and confidence-derived rather than AI consensus or measured market demand.
- **Build configuration contains relative app inputs/output paths.** `vite.vps.config.ts` selects private-app entries, build output and local favicon paths; these are product directory names rather than a personal filesystem location. Its external dependency and favicon references do not themselves clear the dependency or asset licenses.
