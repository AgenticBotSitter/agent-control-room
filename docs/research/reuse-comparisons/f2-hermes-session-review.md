# Independent root review: actual Hermes session-file handler

2026-09-08. Reviewed actual fixture, capture wrapper, source/wheel acquisition
records, preparation/cleanup receipt and complete retained execution JSON. No
candidate rerun, download, installed Hermes, credentials or application changes.

## Accepted evidence

The unchanged pinned handler/helper and actual Starlette FileResponse execute.
The fixture consumes real response bytes through an in-process ASGI sink, not
only a response object's path. Twelve behavioral cases and exit0 are retained.
Root independently parsed actual stdout and deep-compared it to the receipt's
parsed object, checked the current fixture SHA256 against the execution receipt,
recomputed every returned body hash and verified the exact owned root is absent.

Correct same-name file selection, actual empty-session refusal, sensitive-name
refusal, parent/absolute path behavior and deferred-open mutable-byte behavior
are useful E2 observations. They demonstrate why session cwd is not an admitted
export boundary and why a response object/ETag is not an immutable file receipt.
The two successful runs are disclosed: the second captured complete stdout after
the first tool display truncated it. This is not two independent experiments.

## Limits that remain attached

- Wrong-profile/unknown-session404 originates in the synthetic resolver. The
  original handler propagates that decision, but real profile DB authorization
  and dashboard request authentication were not exercised.
- Hashes are computed by the fixture. They are not upstream producer/run claims.
  An opaque browser artifact ID likewise is not a producer identity. Root requested
  a report-only wording correction where the alternative description blurred it.
- No real router dispatch, network disconnect/retry, remote filesystem, symlink
  race, large-file resource envelope or CR attachment admission is established.
- The source/wheel equality checks occurred before import; root checks their
  retained execution evidence, not deleted wheel contents independently. Eleven
  dependency licenses are recorded as PyPI declarations. Exact wheel license-file
  names/text hashes were not retained; redistribution clearance remains open.
- Cleanup receipt says removed and root independently observed absence. This
  covers that owned temporary root, not every possible process or filesystem effect.
  The Python audit hook is not an operating-system sandbox certification.

## Integration disposition

Accept this as evidence that the supported Hermes download handler can provide
bytes, not as completion of general attachments or a security failure of Hermes.
Do not copy its31KB multipurpose router and Python framework closure into the
Control Room server. Prefer calling its existing route where an independently
approved connector already has the required endpoint/profile access.

The next actual fit must be the legitimate source-bound attachment interface,
not a fake completed native-text snapshot. The existing root intake disposition
defines the exact mismatch. Endpoint access/export ownership and multiple-file
metadata remain real integration costs; no extra SSH engine is justified by the
absence of those app-specific pieces. Authenticated remote availability and
producer ownership must not be inferred from the twelve local cases.

This accepts the bounded experiment, not a final all-transport selection. Preserve
the existing upstream remote-media and browser-receipt alternatives for their
different responsibilities; do not rerun these same local path cases merely to
increase the count while the actual attachment seam remains absent.
