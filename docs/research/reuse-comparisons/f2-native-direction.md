# Native connectors and attachment integration direction

2026-09-08. Conditional implementation targets, not complete native compatibility,
common-candidate evaluation or production recovery acceptance.

## Hermes

Use supported upstream structured run/session interfaces through the existing
Control Room adapter. Use the existing session-aware download route for additional
bytes where the approved connector has endpoint/profile access. Do not fork Hermes,
copy its multipurpose Python router into the web server, or create a new SSH/file
transfer engine. Herdr remains advisory observation, not execution/recovery authority.

The actual unchanged download handler/FileResponse has twelve reviewed local cases;
real profile authentication, remote access, containment and mutable files remain
unqualified. Retain current final-text receipts for final text. Additional files
need declared export scope and a separate attachment manifest bound to the actual
project/run/attempt, with protected retrieval and byte/type limits. Do not invent a
completed text snapshot or treat a model-provided path as export authorization.
Existing receipt-store and remote-media routes remain alternatives for their actual
responsibilities, not required duplicate transport layers or proven inferior routes.

## Codex

Use official App Server protocol through the existing bounded TypeScript transport
as the initial integration route. Retain canonical identity, admission, uncertainty
and observer contracts; do not implement a new native protocol/router. This is not
a declaration that the qualification runtime is a complete production connector.

Its current read method scope rejects thread/read and its resume path can start a
new turn. Neither is acceptable as transparent read-only recovery. Implement and
review a separate exact persisted thread/turn inspection path; do not broaden the
qualification allowlist to make a test pass. Distinguish inspect, reconnect/subscribe
and generate-new-turn operations. Never guess IDs, manufacture usage/events or
automatically start again after uncertainty.

The inspected Python SDK is a viable typed-client alternative; its async facade
delegates to the same sync router and does not independently fix the observed
early-event registration concern. It supplies useful supported read interfaces,
but still needs CR identity/result/usage reconciliation. No complete lifecycle or
performance winner has been demonstrated. Retain the existing language/boundary
while addressing its named gaps; reopen if that requires more custom machinery than
an actual supported SDK adaptation, or a compared SDK fixes the relevant failure.

## Acceptance and evidence limits

Required: early same-turn versus stale events, exact-ID read with absent/duplicate/
wrong turn and incomplete views, retained result and attributed usage, interrupted
start, process restart, cancellation/owned cleanup, current RPC environment policy,
credential isolation and supported host qualification. Missing usage stays unknown.
All matched native effects remain gated by existing approvals. No native attempt,
real session resume or credential operation is authorized by choosing this route.

Source/interface comparison and target-specific package/license checks remain open
where documented; this conditional choice does not turn them into passed tests or
owner-only deployment gates. Custom code is limited to required CR scope/binding,
bounded lifetime, observation and attachment admission—not upstream execution or
transfer reimplementation. Production lines removed now: zero.

f2-hermes-intake-disposition.md. Retain all negative and unperformed cases.
