# Independent F7 parser-decision experiment review

2026-09-08; requested source base2052982. Read-only inspection of `f7-parser-decision-fit.ts`, retained direct evidence, actual feed decoder and borrowed parser/reader sources. No reruns, downloads, services or application edits. Author's final narrative/decision was not present when assigned; this reviews the experiment, not an assumed completed recommendation.

## Findings and adoption constraints

1. **P2 — reproducible source identity is recorded, not enforced.** The harness prints `sourceSha256` after reading the decoder but never compares it with an expected pin before transpiling/executing. It also imports existing fast-xml-parser/rss-parser/borrowed modules without version/hash assertions. Thus retained evidence describes the observed source snapshot, but a future run is not an exact-pin refusal harness. Before using this as a reproducible selection gate, explicitly verify the decoder and selected adapter dependencies/source identities, or keep the report's provenance claim limited to recorded identities. No evidence here says the observed run used different source.

2. **P2 for any deletion claim — corrected candidate still reaches through rss-parser for entities.** `rssRequire = createRequire(resolve('rss-parser'))` resolves `entities` from the incumbent dependency closure. Removing rss-parser would break that resolution, even though candidate `parseString` itself uses fast-xml-parser. The compatibility snippet also adapts rss-parser's MIT strip algorithm. Count a supported explicit entities dependency/import and attribution in the proposed removal cost; prove the candidate works without resolving through the removed package before claiming uninstallable closure. This is a current prototype dependency, not proof consolidation is impossible.

## What the evidence actually establishes

- The actual full `decodeAbsFeed` module runs with only the `rss-parser` import substituted. Its story building, canonicalization, curation, identifiers and policy stay in place. Same-realm CommonJS evaluation preserves the plain-object digest behavior. This is a **new narrow adapter around actual fast-xml-parser**, not the unchanged borrowed `parseFeed` implementation taking over the decoder, and not a full rss-parser clone.
- Eighteen fixed synthetic XML fixtures compare complete returned JSON or public error outcome. The naive adapter matches14; HTML entities, Atom XHTML, bad RSS date and bad Atom date differ. Added compatibility handling makes all18 match, including digest-bearing output. The retained receipt supports those exact counts. It does not establish all RSS/Atom/RDF variants, namespace semantics, duplicate/mixed content, real publisher inputs, or whole-application migration.
- Some parity cases legitimately match a rejection/empty or partial result, not successful content extraction. “Atom summary only” parity is not evidence the summary is preserved: the adapter does not map `i.summary`. Preserve the actual expected semantics when describing individual cases.
- The borrowed `parseFeed` test independently verifies260 reversed dated inputs produce250 sorted retained entries with exact first/last URLs. The real borrowed reader independently checks undated quiet baseline, repeat snapshot and one new item across three injected reads. Those are useful upstream baseline behaviors, **not evidence that the candidate adapter ran through the collector, archive, database or research-task API**.
- DTD/NUL and item-limit rejection retain existing decoder checks. No new network, agent, DB or live reader boundary is qualified. Runtime mutable `compatibilityMode` is research-only experiment control, not a production-safe concurrent parser configuration.

## Strongest alternatives and cost

Retaining rss-parser3.13.0 is a credible low-change baseline: it already supplies feed-specific normalization, dates and entities. Existing fast-xml-parser5.11.0 plus a narrow compatibility adapter could avoid a second XML stack, but introduces feed-shape compatibility code and possibly explicit entities dependency/notices. Reusing borrowed parser output with a policy translation layer remains a distinct alternative; its250-cap and quiet baseline semantics must not silently replace the decoder's100-item refusal and provenance contracts.

No production lines are removed by this experiment. The real decoder's provenance, policy and curation remain; most replacement cost is the parser import/type surface plus adapter and compatibility maintenance. Before final selection, reconcile remaining rss-parser consumers, explicit dependency closure and measured maintenance/removal benefit. Do not infer a winner from18 passing corpus examples or choose retention solely because broader edge cases are untested. Preserve the successful adapted contender for a fair next decision.

Disposition: useful bounded full-decoder corpus fit and independent borrowed-parser baseline. Conditional selection evidence only; exact reproduction guard and incumbent-dependent entity resolution must be accounted for before a removal-ready implementation packet. No whole-F7 or whole-application acceptance.
