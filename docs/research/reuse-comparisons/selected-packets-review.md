## Findings requiring a document correction

Current package script runs the build followed by `node --import tsx --test` over25 compiled test files **without `--test-concurrency=1`**. Running one package script at a time does not prevent its Node test runner from launching many memory-heavy file processes. Specify a supported serialized compiled-test invocation or require a reviewed script correction before this gate on constrained hosts. Do not silently weaken/drop compiled assertions. This is a source-backed risk, not a measured new OOM.

2. **P2 — carry the selected extractor's execution bounds into IP-02 acceptance.** DR-07 explicitly preserves bounded DOM memory/time/output, and the source research distinguishes inert DOM parsing from fetched-resource/script execution. IP-02 currently lists oversized content but omits an explicit DOM execution/time/output bound and no-network/no-script check. Plain-text presentation and a64KiB storage policy do not establish parser memory/time safety. Add these as root-approved design/acceptance requirements, with existing retrieval controls retained; do not delegate a new unrestricted fetcher or invent numeric limits in this review. A held/pathological synthetic extraction and rejected external-resource/script effects should be represented proportionally to the chosen implementation boundary. This is not a request for another extractor contest or publisher-general quality guarantee.
