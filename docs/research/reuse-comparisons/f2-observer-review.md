# Independent RC2 observer comparison review

2026-09-08. Source/receipt review only; no reruns, downloads or native execution.
Reviewed `f2-observer-fit.md`, direct evidence JSON, authored harness/peer, actual
retained SDK entrypoint, CR decoder/result/observer and runtime/controller binding.
Root retains final selection and acceptance.

**No blocking finding for the report's narrowly stated conclusions.** The candidate
is actually the public SDK, while the observer bridge is deliberately naive and
unsuccessful. The report does not confuse those facts or accuse current production
of the research bridge's missing guards.

## Verified distinctions

- Four pre-import hashes match current bytes, including actual SDK dist/index.js.
  Public Codex/resumeThread/runStreamed runs its real child spawn, readline and event
  parsing against the finite authored emitter. The emitter is not native Codex and
  performs no session restoration; the report says so. Exact requested resume ID is
  asserted from each peer argv trace.
- All seven scenario receipts agree with source and narrative. Wrong-thread changes
  SDK thread.id; projection still succeeds because the harness ignores the decoder's
  nativeThreadId side return. Actual production isolated-runtime checks the resumed
  response against request.nativeThreadId before binding, and isolated-controller
  independently checks equality. No production identity regression is established.
- Late agent-message digest is an out-of-band decoder return with no event; the
  harness updates it after terminal. Result projection's late-event refusal cannot
  guard that side channel. This is a real composition risk for a proposed SDK bridge,
  not evidence that the existing App Server observer admits post-terminal activity:
  observer.observe refuses once terminal and runtime stops its notification loop.
- Late usage creates actual events and is rejected. The failed-with-usage synthetic
  extension produces failed projection with zero counters; that is not a promised
  SDK failed-event usage field or evidence of zero provider cost. Cache-write counter
  is retained by the synthetic streamed object but absent from CR's mapped counters;
  receipt and report avoid claiming complete billing accounting.
- Nonzero exit is a real SDK transport rejection. The separate unsafe projection
  succeeds only because the research harness intentionally projects accumulated
  frames despite that rejection. EOF lacks terminal and projection refuses it.
  Report correctly requires transport/uncertainty precedence for any adapter.
- Actual observer is instantiated with synthetic ticket and fake settlement sink.
  It ignores SDK dotted event names; naive renamed turn/started fails. That test alone
  would be weak because bindTurn was never called, but source supplies the decisive
  reason: this SDK stream has no actual native turn ID to bind and the current
  observer requires it. No invented ID or successful durable settlement is claimed.

## Evidence and cleanup scope

E3 is defensible only for actual SDK synthetic transport crossing unchanged CR
decoder/result functions. It is not E3 observer settlement, authorized broker intake,
durable recovery or native provider qualification. Fake ledger records ambiguity
because the harness explicitly calls disconnect, not because a native disconnect
was observed by an integrated production pipeline.

The peer source has no child-spawn behavior. Harness reads a trace for each scenario,
checks all recorded PIDs gone before removing its root, and evidence says clean=true,
remainingCount=0. Independent read-only absence check confirmed that exact root is
gone. Retained SDK source remains intentionally available; it is not falsely counted
as newly acquired or cleaned. Parent RSS excludes child/native runtime and is
appropriately scoped. Four-second abort is not a whole descendant containment proof.

asserted than the negative cases: fixture explicitly asserts argv, observer failures
and selected mismatch/error outcomes, while full17/8/5/3 counter equality and baseline
thread/result equality are visible in the receipt rather than asserted as a bundle.
Before reusing this as a regression gate, add those baseline assertions and exact
seven-mode coverage. No rerun is required to accept the observations already saved.

Keep the strongest alternatives open: an intentionally job-oriented SDK boundary,
actual Python SDK/App Server integration preserving native IDs, and current direct
App Server transport. Absence of turn ID is a mismatch with this exact observer,
not grounds to reject all SDK use. No production deletion or final winner is earned
