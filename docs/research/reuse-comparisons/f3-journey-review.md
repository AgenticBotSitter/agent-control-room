## Root integration decision

Retain current result identity, byte verification and review authority for this
responsibility. Do not import MessageRow's prose-to-Approve/Deny logic into result
review, execution consent or Needs Me. Neither a disabled callback nor a no-op
Approve button is an acceptable adaptation: those would misrepresent what the user
is approving. Future transcript presentation can reuse upstream rendering pieces
only with explicit separation from authoritative action controls.

This closes the question of whether the **unchanged** MessageRow should replace
our result/review controls: it should not. It does not select the best transcript
renderer. That decision still compares actual rendering/link/media closure and
adaptation cost against existing UI and other surveyed candidates. No new custom
chat renderer is justified by rejecting this one action heuristic.
