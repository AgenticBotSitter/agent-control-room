## Confirmed integration gap

Pinned `gateway/platforms/api_server_runs.py` completes runs with
`output=result.get("final_response", "")` and usage (line 583). GET status returns that
status record (line 654 onward). No call to the new media retrieval hook appears in
this module. The new hook is in the platform's media-delivery path instead.

Control Room's `src/harness/hermes-native-v1/protocol.ts::readStatus` reads final text;
`src/artifacts/v1/native-results.ts::checkedResultBytes` validates bounded UTF-8 results.
Neither is a general remote-file receiver. A `MEDIA:` path in text is not proof that
bytes were retrieved, retained, authorized or delivered. Do not fetch arbitrary paths
from model text or claim that a gateway download is already a canonical project result.

## Reuse / remaining work

Prefer Hermes's native retrieval when a supported delivery surface exposes verified
files. Do not copy its shell transport into the trusted TypeScript controller or build
a second SSH implementation. First inspect the pinned gateway's authenticated file/
media API and capability/version surface for exact-profile access to retrieved bytes.
If there is no run-bound supported handoff, record that API gap before proposing a
small upstream extension; avoid a private Hermes fork as the default.

The necessary Control Room bridge associates actual bytes and receipts with project,
task, attempt, producer and allowed recipients. Preserve the harness-neutral local/R2
artifact path so Codex is not dependent on a Hermes-only Group Chat. A gateway cache
is transient transport storage, not our durable review evidence or PostgreSQL authority.

Still untested: full gateway denylist/strict-mode hook, live SSH/Modal/Daytona/Singularity/
Vercel, named-profile sessions, reconnect/recovery, byte integrity beyond transfer
framing, file-result visibility in the private website, and retention/cleanup ownership.
The base transport follows symlinks; security screening is the caller's responsibility.
Its 50 MiB gateway cap and 300-second fetch timeout are not automatically appropriate
for our current result receiver. No application contract or limits were changed.

E06's unmerged RoomLink work remains relevant for independent bot handoff, not a
prerequisite to ordinary remote task output. New custom infrastructure remains unjustified.
No application dependency, native installation, provider call or runtime wiring added.
