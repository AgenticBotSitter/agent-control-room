## Findings

1. **The new local submission cannot be used through the webpage.** `private-app/app/task-approval.tsx:42-49` renders the only `PrivateTaskSubmission` instance only when `state.receipt` exists, and binds its digest to that signed approval receipt. Mac-local tasks deliberately have no signed approval packet. The new GET `preview` is not read or displayed by any `private-app` component (`src/web/v1/task-http.ts:79-87`), and the browser submission client has no preview operation. A normal owner can prepare and assign a local task, but never reaches a Submit button or echoes the server-derived digest through the webpage. This fails section 14's stated owner-webpage flow; an API-only test does not cover it. Keep the hosted signed-approval path intact while providing a distinct local preview/confirmation path.
2. **The owner-review profile SQL guard does not require an owner author.** `db/migrations/0086_mac_local_owner_review_profile.sql:60-64` accepts any same-tenant `human` identity as `createdBy`, including an inactive human without an owner grant. The comment claims the owner is the author; the test set has no same-tenant non-owner case (`tests/mac-local-owner-review-profile-guard.test.ts:62-76`). A caller holding the web login and review integrity key can register the fixed profile while attributing it to a different human. Bind the author to the active owner identity/grant (or explicitly narrow the security claim and prove the misattribution cannot affect accepted records).
3. **The fleet-signal guard does not confine writes to the three provisioned local workers.** `db/migrations/0087_mac_local_fleet_signals.sql:26-30` accepts any existing node whose payload declares `macos`, `mac-local/v1`, and `local-only`; it does not check the installation tenant, active state, provisioned worker IDs, or key pin. With the grants at `db/roles/task_coordinator_roles.sql:64-68`, a coordinator login can append fresh `reported` capability/telemetry signals for another local-looking or revoked node and then update its current row. The stricter envelope/history checks do not close this node-scope gap. A negative test with another same-tenant local-looking node and a revoked node is needed; decide the precise permitted node binding rather than relying on self-described payload fields.
