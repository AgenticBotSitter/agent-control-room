# Package 5 section 12: first-owner command cannot yet be completed safely

Status: source work can continue, but do not run `first-owner-vps` against any database or mark the disposable rehearsal passed until these contract gaps are decided by the lead. The live database and Tailscale were not touched.

1. Section 12.A/C puts `CompletionGateStoreV1.provisionTenant` in the one VPS-local transaction. That method requires the Mac's private `keys.review` to calculate an authenticated integrity row and an independent rollback-checkpoint store. Section 12.B forbids a key in the shareable manifest, and the VPS command has no access to the Mac's protected checkpoint file. The current Mac-local provider tries to provision at startup using the coordinator role, but that narrow role intentionally lacks `INSERT` on `control_completion_gate_integrity`. This is not solvable by reordering `mac:up` or widening the login. In addition, the existing checkpoint store writes to a file before the database transaction commits, so a failed commit can leave an orphaned checkpoint. Specify an explicit, recoverable one-time initialization protocol that preserves key custody, checkpoint separation, and fail-closed behavior.

2. The three node rows require `softwareFingerprint = sha256({ purpose, nodeId, workerId, adapterId })` in `seedMacLocalNodeV1`. Section 12.B permits adapter and node IDs in the manifest but not worker IDs or those derived fingerprints. The VPS cannot reproduce rows that `mac:up` verifies against protected enablement without either more non-secret input or a changed shared fingerprint contract. Choose one; do not infer a worker ID from a node ID.

3. Section 12.C says a repeat run keeps every matching row and refuses a differing row. The row comparison needs an exact policy for time-dependent fields, including node `enrolledAt`, `createdAt`, and `updatedAt`; a one-time manifest `createdAt` can make them deterministic. It also needs a precise receipt schema. This branch proposes `{ schema: "control-room.mac-local-first-owner-receipt/v1", created: number, kept: number, fingerprints: { [nodeId]: digest } }` with exact keys. Confirm or amend before using the receipt in a live handoff.

Source work already removes automatic completion-gate initialization from the task provider. That change is intentionally fail-closed: it will not make the worker path usable until the one-time setup can create the authenticated integrity row and independent checkpoint together.
