# Package 4 fresh-install findings for Claude

**Branch:** `codex/mac-w3-provider-4`. **Status:** provider assembly paused at the trust decision's “if assignment needs more than readiness, stop and ask” rule. These findings concern the disposable rehearsal database; no production data was changed.

1. **The local node is not bootstrapped.** `scripts/mac-local/bootstrap-owner.ts` creates the tenant, workspace, owner, and adapter registry rows. It never creates `control_nodes(id='mac-1')`. `FleetSignalStore.ingestAuthenticated` requires that node before it records the capability and telemetry signals required for assignment. The only current `control_nodes` insert in source is `NodeEnrollmentStore.complete`, the remote key/enrollment ceremony. Please decide the local owner's reviewed, idempotent node bootstrap (including the required row payload and identity binding). Package 4 should not invent a remote enrollment or silently assert the node exists.
2. **A new project's review profile is not provisioned.** The provider's three task templates need a project-specific `acceptanceProfileId` and digest, and result submission verifies the saved profile. Neither `mac:bootstrap-owner` nor project creation registers a `CompletionGateStoreV1` profile. Please specify the accepted local profile and when it is registered for each project, within the 16-template/restart limitation already accepted in the trust decision. A default ID without a saved profile would leave results unable to reach pending review.
3. **First-run task key generation needs a setting source.** `mac:prepare-task-runtime` requires `--hermes-profile`, `--hermes-provider`, and `--hermes-model`; `mac:up` currently calls none of these and has no settings input. Please choose whether first-run `mac:up` accepts these owner-selected values or setup creates the protected file before `mac:up`. Existing valid files must remain unchanged.

The independently placed checkpoint store has been merged into this isolated branch and its nine tests pass. The local Claude queue bridge is implemented and type-checked here. No provider has been made to claim readiness without the prerequisites above.
