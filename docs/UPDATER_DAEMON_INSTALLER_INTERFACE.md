# Updater daemon installer interface

Item 5 owns daemon generation and the adapter in
`src/installer/v1/macos-launch-daemon-installer.ts`. Item 4 owns the privileged
implementation. Both sides share only
`src/installer/v1/macos-launch-daemon-elevated-contract.ts`.

The item-4 installer is already running as root after the one attended sudo. It
implements `MacosLaunchDaemonElevatedPortV1` in process; it must not start a
second sudo command. The request binds the exact resource inventory, root-owned
log-directory and pre-created log-file specifications, service start/rollback
order, and PostgreSQL stop proof.

The same request owns the generated `Protected/config/backup.json` resource.
It writes that file as the service account with mode 0600 before bootstrapping
the nightly job. The configuration is generated by the shared nightly-backup
configuration module; it contains no credential, only the protected password
file reference, fixed database login, root-level backup output, protected lock file, ledger pin and
retention count.

The request also owns `Protected/config/fleet-gateway.json`. The installer writes
it as the Control Room service account with mode 0600 before bootstrapping the
gateway. Its database logins are dedicated to fleet and work-intake duties, its
listener is fixed to loopback by the gateway runtime, and worker authentication
uses the per-worker credentials loaded from PostgreSQL. Forwarded client-address
headers remain disabled for this Mac-local daemon.

The request's `writableDirectories` are the item-4 R-FS boundary. Item 4 must
create each path component with `mkdir`, reject symlinks with `lstat`/no-follow
opens, and apply the declared root owner, service group and mode with `lchown`
before any dependent daemon is bootstrapped. The nightly output and lock
directories are root-owned, group-writable by the account that runs the job,
and never inferred from the invoking user.

Before creating or reusing any declared service account or group, item 4 must
also reject a name, UID or GID collision. A matching name with a different ID,
or a requested ID already owned by another principal, is an install refusal;
the helper must not silently adopt or renumber it.

For a database stop, the helper terminates service sessions, boots the launchd
job out first, and only then verifies that `postmaster.pid` is absent, the
socket is closed, and `pg_controldata` reports a shut-down cluster. A failed
proof returns `rolled_back` or `uncertain` before any clone or link change.

The legacy `nightly-backup` job remains in the generated bundle until updater
item 19a provides its locked dump and restore verification. Its removal must be
the same merge as item 19a.

## BRANCH_ALIGNMENT

Updater item 5 generates exactly six plists: PostgreSQL 17, supervisor, fleet
gateway, nightly backup, updater and updater guard. The nightly-backup plist is
deliberately retained on this branch and may be removed only in the same change
that lands updater item 19a.
