## Rules for closing a packet

One decision must name its responsibility, all surveyed viable alternatives, executed
discriminating cases, exact adaptation/removal scope and unresolved target gates.
Local setup failure is not candidate rejection. Missing local decisive evidence is
not an owner gate. Native provider/host evidence stays separate from local fit.
Don't score unknown cost/performance as zero or let a library's unrelated features
win the comparison. Prefer complete interfaces, not many successful fragments which
still cannot perform the user's workflow.

Shared closure gate for **every** candidate-responsibility decision: account for all
nine mandatory dossier fields in REUSE_COMPARISON_PROGRAM.md. Link exact pins,
implementation and upstream tests (read versus run), dependency/asset/license scope,
actual application mapping, reproducible cases/failures/cleanup, adaptation/removal
cost, measured resources with workload/platform/unknowns, maintenance/security/update
evidence, and the strongest viable alternatives. Apply the published pass/fail and
weighted rubric with explanations/ranges; missing evidence stays unknown, not zero.
Require independent challenge and disposition of material findings. This is a
checkable completion gate, not an invitation to repeat already sufficient evidence.

Cross-packet journey gate for RC1/RC2/RC3/RC4/RC7: reconcile the **actual ordinary
task → retained result → review → linked revision** path with synthetic workers and
current application services. Trace canonical IDs/attempts and restored/replayed
state, including uncertain start and delayed result. Reuse existing equivalent
journey evidence when source/pins/scope match; rerun only changed seams. A collector,
SDK terminal event or valid JWT alone does not close that local journey. Actual
provider/owner-qualified execution remains the separate target gate.
